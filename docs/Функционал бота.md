# MAX Бот — полный функционал

## Что это

Бот для мессенджера MAX (`platform-api.max.ru`) — рабочий инструмент для сотрудников ОКЭ филиала АО «РИР» в г. Северске. Интегрирует расписание заданий, базу поверок ФГИС, биллинг ГВС, загрузку фото на Я.Диск и алгоритмы работ.

---

## Главное меню

| Кнопка | Доступ | Описание |
|--------|--------|----------|
| Поверка приборов в АРШИН | все | Поиск поверок через ФГИС |
| Расчёты | все | Калькуляторы (сейчас один — тепловая нагрузка) |
| Алгоритмы | все | Пошаговые инструкции |
| Электронные журналы | все (биллинг — allowlist) | Объединённое меню журналов |
| Загрузка фото на Я.Диск | все | Загрузка фотографий по объектам |

---

## 1. Поверка приборов в АРШИН

Поиск поверок через API ФГИС (`fgis.gost.ru/fundmetrology/eapi/vri`).

**Форма поиска** — заполняются любые поля:
- Поверитель (по умолчанию ООО «МЭР», можно ввести своего)
- Год (2021-2026)
- Номер прибора
- Тип / обозначение

**Результат:** до 5 приборов с данными — дата поверки, срок действия, документ, пригодность, плюс **короткая ссылка через clck.ru** на публичный реестр ФГИС.

**Технические особенности:**
- Автоподбор кириллица/латиница (МЭ / ME) — ищет оба варианта
- Варианты кавычек для ООО (`"..."` и `«...»`)
- Обработка 429 (rate limit) с паузой 0.6 с и повтором
- Лог в `log/arshin.log` при `ARSHIN_DEBUG=1`

---

## 2. Расчёты

**Расчёт тепловой нагрузки** (по объёмам) — по вводу параметров:
- Геометрия помещения (высота, объём)
- Расчётная температура
- Температура наружного воздуха
- Объём подвала

Формирует расчётную Qот (нагрузка отопления).

---

## 3. Алгоритмы

Пошаговые инструкции для полевых работ. Каждый алгоритм — набор пронумерованных шагов с навигацией «← Назад / Далее →».

Сейчас доступны:
- **Ввод ИПУ ГВС** (8 шагов) — от приёма заявки до бланка акта АО «РИР»
- **Отключение ИПУ**
- **УУТЭ** (узлы учёта тепловой энергии)

Расширяется добавлением файлов в `algorithms/*.rb` и записью в `services/algorithms_service.rb`.

## 4. Электронные журналы

Объединённое подменю. Два раздела. Если пользователю доступен только один — бот пропускает подменю и **сразу открывает** этот раздел.

### 4.1 Электронный журнал (доступен всем)

Чтение Google Sheets с ежедневным расписанием (XLSX-файл на 194 вкладки).

**Логика определения текущей недели:** бот сканирует первые 25 вкладок, находит ту где в B1 стоит «Время» и сегодняшняя дата попадает в диапазон. Имя вкладки не анализируется (там бывают опечатки).

**Функции:**
- **Выбор чьё расписание смотреть** — список сотрудников из шапки (служебные записи типа «необходимо потключить в ИТП» отфильтрованы). Если ты подписан — твоё имя со звёздочкой «⭐ Моё расписание» в верху списка
- **Навигация по дням** — Пред./След./Сегодня/Выбрать день
- **Кнопки 📷 за каждой задачей с адресом** — извлекает адрес из текста задачи (например «калинина,56-31» → запрос «калинина 56»), ищет папку на Я.Диске и открывает сразу загрузку фото
- **«Следующее задание» в режиме загрузки фото** — после загрузки одного объекта кнопка переключает на адрес следующей задачи в расписании
- **К списку людей** — вернуться к выбору сотрудника

**Подписка на уведомления:**
- В расписании любого сотрудника — кнопка «🔔 Подписаться на уведомления» / «🔕 Отписаться»
- Выбор имени теперь **не равен** подписке — можно смотреть чужие расписания без подписывания
- Подписан на себя → каждое утро в 8:00 (пн-пт) приходят задания на день
- **Уведомления об изменениях** — раз в 15 мин в рабочее время (пн-пт 8:00-17:00 по Новосибирску) бот сравнивает актуальное расписание со снимком. Если что-то поменялось **в сегодняшнем или завтрашнем** дне — шлёт diff (➕ добавлено / ✏ изменено / ➖ удалено)
- После каждого уведомления снимок обновляется → в следующий раз показывает только новое

**Фоновые задачи:**
- Обновление таблицы каждые 15 мин в рабочее время, иначе раз в час
- Утренняя рассылка через `rufus-scheduler` (cron `0 8 * * 1-5`)
- Проверка часового пояса через `SHEETS_TZ_OFFSET` (на Windows Ruby не применяет `ENV['TZ']`)

### 4.2 ГВС биллинг (доступен allowlist)

Чтение **и запись** в Google Sheets «ГВС биллинг». Доступ только user_id'ам из `BILLING_ALLOWED_USER_IDS`. Google Sheets API с OAuth (автообновление access-токена через refresh-токен раз в час).

**Меню:**
- 🔍 Поиск по абоненту / адресу
- 📅 Создать следующий месяц

**Поиск (токенизированный):**
- Запрос разбивается на токены по пробелам, запятым, дефисам, точкам, точкам с запятой, слешам
- **Все токены** должны встречаться в объединённой строке «ОКЭ + адрес» (регистр не важен)
- `транспортная 32` находит `Транспортная, 32`
- `калинина 56 автоматика` найдёт строку где есть все 3 слова в любом порядке

Результаты с пагинацией (8 на страницу).

**Карточка объекта:**
```
📋 Кузнецова Л.Т.
📍 Коммунистический, 74

Дата ввода в эксплуатацию: ...
Дата следующей поверки: ...
Заводской номер: 14-286157

Дата передачи конечных: ...
Конечные показания: 238,00

Уже введены текущие:
  дата: ...
  показания: 259,00
```

Кнопки: `✏ Ввести показания`, `🔍 Проверить в АРШИН` (если есть заводской номер), `К результатам`, `В меню`.

**Ввод показаний:**
1. Число (валидация: `123` или `123,45`, точка и запятая равноправны)
2. Дата (`ДД.ММ.ГГГГ`, либо «сегодня», либо кнопка «Сегодня»)
3. Запись в Q (дата) и R (значение) через Sheets API
4. Автоматическое перечитывание строки → обновлённая карточка

**🔍 Проверить в АРШИН** (кнопка в карточке):
- Бот ищет запись по заводскому номеру, **перебирая годы от 2019 до текущего** (новейший год → самая свежая поверка)
- Применяет фильтр: `require_all_keywords: [счетчик, вод]` + `reject_keywords: [тепл, газ, электр, энерги]` → отбрасывает теплосчётчики, манометры, электросчётчики и прочий шум, оставляет только водомеры
- Возвращает блок с актуальными данными из ФГИС и автосверкой с датой из таблицы (✅ совпадает / ⚠ расходится)
- **Короткая ссылка на ФГИС** через clck.ru с указанием активного года

**📅 Создать следующий месяц:**
- Сначала **подтверждение** (Yes/No с описанием что произойдёт)
- Определяет текущую вкладку (первая в списке = самая новая)
- Вычисляет имя: «Апрель 2026» → «Май 2026», декабрь → январь следующего года
- Дублирует вкладку (`duplicateSheet` API) и вставляет в начало списка
- Переносит данные построчно:
  - Если текущие показания (R) **непустые** → новые конечные = текущие (Q→O, R→P)
  - Если текущие **пустые** → старые конечные (O, P) **остаются** без изменений
  - Колонки Q и R в новом месяце очищаются
- Защита от дублей: если вкладка «Май 2026» уже есть — ошибка
- **После создания** — бот сразу присылает список **истекающих поверок до конца нового месяца** (а не фиксированные 30 дней)

Поскольку новая вкладка вставляется в начало, **все последующие поиски и вводы показаний автоматически идут в новый месяц** без доп. настроек.

## 5. Загрузка фото на Я.Диск

OAuth-токен Яндекса (один на весь бот), структура папок `/Фото узлов/Фото/`.

**Вход:**
- Показываются корневые категории (МКД, ГСПО, Встройка и т.д., 12 штук) с **пагинацией по 10** (← Пред. | 1/2 | След. →)
- Либо набрать текст поиска

**Поиск:** рекурсивный по всему дереву (глубина 4). Два слова в запросе = оба должны встречаться в пути (`калинина 56` находит `МКД/Калинина/56`). Результаты **с пагинацией** (8 на страницу).

**Навигация в дереве:**
- Если папка содержит подпапки (категория) → **drill-вид** с их списком, пагинация по 10, кнопка «➕ Создать подпапку»
- Если подпапок нет (лист) → режим загрузки фото
- **В режиме загрузки** также доступна кнопка «➕ Создать подпапку» — можно создавать подпапки и на лист-уровне

**Загрузка:** пользователь просто шлёт фото в чат.
- Бот извлекает прямой URL из attachment (`payload.url`)
- Через remote-upload API Яндекса (`POST /resources/upload?url=...&path=...`) — Я.Диск сам качает с URL и сохраняет
- Имя файла: `photo_YYYYMMDD_HHMMSS_<photo_id>.jpg`
- Подтверждение «✅ Загружено: +1 (всего N) в папку X»

**Кеширование дерева папок:**
- 2914 папок сканируются параллельно (8 потоков) примерно за 4 минуты
- Результат сохраняется в `cache/yadisk_folders.json`
- TTL 60 минут
- При старте бота — прогрев в фоне (если кеш есть — мгновенно из файла)
- **Stale cache strategy:** если кеш протух — отдаём старые данные сразу и фоном запускаем пересканирование. Пользователи никогда не ждут скан.

**Создание новой папки:**
- Из поиска (если ничего не нашлось), из drill-вида, из режима загрузки
- Создаётся в текущем родителе
- Кеш инвалидируется

## 6. Служебные функции (фоновые)

### Лог пользователей (задел для allowlist)
Каждый пользователь при первом обращении попадает в `data/max_users.json` (user_id, имя, фамилия, chat_id, timestamp). При повторных обращениях запись не меняется. Для фильтра «доступа к боту только сотрудникам».

### Allowlist биллинга
`BILLING_ALLOWED_USER_IDS` в `.env` — через запятую user_id'ы, кому доступен биллинг. Пустая переменная = никто.

### Дедупликация сообщений
Все входящие события имеют уникальный ключ `chat_id:mid:seq:ts`. Кеш из 5000 последних ключей с TTL 10 мин — защищает от повторной обработки одного сообщения, если MAX пришлёт его дважды.

### Thread-safe состояния
`MAX_USER_STATES` и `MAX_PROCESSED_KEYS` под mutex'ами — одновременные запросы нескольких пользователей не ломают друг друга.

### Снимки расписания
`data/task_snapshots.json` — по каждому подписанному пользователю хранится слепок заданий на сегодня и завтра. Используется для diff-уведомлений. Старше 2 дней автоочищается.

## Запуск и управление

Работает как Windows-сервис через NSSM. Путь: `C:\nssm\nssm-2.24\win64\nssm.exe`, имя сервиса `MaxBot`.

**Команды PowerShell:**
```powershell
Get-Service MaxBot             # статус
Start-Service MaxBot           # запустить
Stop-Service MaxBot            # остановить
Restart-Service MaxBot         # перезапустить

Get-Content C:\max_bot\log\max.log -Tail 30 -Wait   # следить за логом
```

**Переустановка сервиса и подробности** — см. `docs/Управление ботом.txt`.

## Интеграции — чек-лист переменных в `.env`

**Секреты:**

| Переменная | Что это |
|------------|---------|
| `MAX_BOT_TOKEN` | Токен бота в MAX |
| `YANDEX_DISK_TOKEN` | OAuth-токен Яндекс.Диска (один на всех) |
| `GOOGLE_OAUTH_CLIENT_ID` / `_SECRET` / `_REFRESH_TOKEN` | Креды Google API для биллинга |
| `SHEETS_DOCUMENT_ID` | ID таблицы расписания (xlsx, только чтение) |
| `BILLING_DOCUMENT_ID` | ID нативной Google-таблицы ГВС биллинга |

**Доступ и поведение:**

| Переменная | Что это |
|------------|---------|
| `BILLING_ALLOWED_USER_IDS` | user_id через запятую — кому доступен биллинг |
| `BILLING_POVERKI_HORIZON_DAYS` | Кол-во дней вперёд для выборки истекающих поверок (используется как fallback) |
| `ARSHIN_SERIAL_MIN_YEAR` | Нижняя граница года для `find_by_serial` (по умолчанию 2019) |
| `SHEETS_TZ_OFFSET` | Часовой пояс для проверки «рабочее время» (по умолчанию +07:00) |
| `SHEETS_WORK_HOUR_FROM` / `_TO` | Окно рабочего времени для уведомлений (8-17) |
| `SHEETS_REFRESH_WORK_MINUTES` / `_OFFHOUR_MINUTES` | Интервал обновления таблицы |

Все остальные переменные `.env` — нечувствительные настройки (интервалы, пороги, пути и т.д.).
